## 1. 一句话

**私董会** = 每个人围绕自己搭的一张日常工作台：用自然语言跟项目组、人、事沟通，连接外围应用里的信息与决策；查验资料、推进事项。投资、消费等 **高危决策必须本人手动确认，严禁跳过**。

它不是演示壳，也不是「替你自动花钱」的黑盒——而是超级个体日后可能天天坐着干活的界面。

---

## 2. 三层模型（实现时心里要有）

```text
┌─────────────────────────────────────────────┐
│  私董会工作台（自然语言 · 聊天优先）           │  ← 主界面：推进、查验、对齐
├─────────────────────────────────────────────┤
│  外围应用连接（信息流 + 待拍板队列）           │  ← Connectors / Skills / 外部 API
├─────────────────────────────────────────────┤
│  高危确认闸（独立确认层 · 可审计）             │  ← 投资/消费/不可逆变更等
└─────────────────────────────────────────────┘
```

| 层 | 做什么 | 明确不做什么 |
| --- | --- | --- |
| 工作台 | 对话驱动：问进度、要资料、发任务、看结果 | 不把 Demo/样例当成「已替你办完」 |
| 外围连接 | 拉信息、同步状态、暴露「待你拍板」项 | 不静默替用户完成高危动作 |
| 确认闸 | 高危动作单独确认、留痕、可拒 | **禁止**一键静默通过 / 默认勾选代批 |

---

## 3. 三条硬口径（改名改屏也保留）

### 3.1 高危动作 → 独立确认层，不可一键静默过

- **高危**至少包括：投资、消费/支付、转账、签约、不可逆删除、对外以用户身份发送关键指令等（清单可扩，原则不变）。
- 必须有 **独立确认 UI**（审批卡片 / 确认面板），展示要点与后果；用户明确通过或驳回后才执行。
- **严禁**：自动勾选「以后都同意」、倒计时代批、把确认埋进普通 Toast、用 Demo 假通过冒充真闸。
- 代码侧：审批 / confirm 路径注释须写清「为何不能旁路」；契约与手测把「可解除 / 可驳回」当门禁，不只 `alert` 占位。

### 3.2 外围连接 = 信息流 +「待你拍板」队列

- 连接器既喂 **信息**（只读/同步），也喂 **决策请求**（须进待拍板队列）。
- 工作台要让用户分得清：哪条是「知道就行」，哪条是「不点确认就不会发生」。
- 队列可本地 demo 建模，但产品语义上不得把「待拍板」做成不可操作的装饰 pill。

### 3.3 主界面是工作台，不是演示壳

- Chat / Demo / Skills / Memory 等入口，点完必须有 **页面变化**（成功内容或明确失败态）；空转即拒收（验收硬门禁）。
- Demo 是 **样例路径**，用于验证链路与终态；不得暗示「演示过 = 生产决策已代劳」。
- 「运行中…」必须有终态（结果或标出卡点的失败/超时），禁止无限转圈。

## 4. 与现有实现的对齐提示（给编码/测试）

| 区域 | 跟定位怎么接 |
| --- | --- |
| 审批 pill / 确认面板 | 可解除计数、可驳回；非仅 `alert`；真闸与本地 demo state 要在注释里分清 |
| Connectors / 百炼等 | 外围信息与模型推理；高危结果若触发动作，仍须回确认闸 |
| Chat / 顶栏 Demo | 同链出 insights 或明确失败；是工作台能力的样例，不是替身董事会 |
| Memory /「显示演示内容」 | 真反馈 + 契约；演示内容须可辨为演示 |
| 审计 / 日志 | 确认通过与驳回都应可追溯（谁、何时、对什么） |

口令与 tip 验收以项目组房内 HOLD 为准；**本文不替代 tip 口令**，只约束「为什么这样写」。
